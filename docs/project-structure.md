# Структура проекта

Текущая библиотека остаётся в `assets/`; её пути используются в каталоге.
Ниже целевая структура: папки приложения и тестов добавляются вместе с кодом,
а не как пустые заготовки.

```text
app/                     Python / FastAPI
  main.py                HTTP API и раздача интерфейса
  composition.py         Подбор и размещение объектов
  catalog.py             Загрузка и проверка библиотеки
  ai.py                  Разбор метафор через модель
web/                     Интерфейс без обязательной сборки Node.js
  index.html
  styles.css
  app.js
assets/
  source/L/              Оригинальные SVG размера L
  source/S/              Оригинальные SVG размера S
  catalog.json           Названия, теги, варианты, габариты и хеши
scripts/                 Подготовка библиотеки и инструменты проверки
tests/                   Проверки композиции и векторного экспорта
docs/                    Архитектура, аудит, инструкция для демонстрации
examples/                Отобранные итоговые композиции для сдачи
requirements.txt         Зависимости сервера (добавляются с сервером)
.env.example             Шаблон настроек без действующих ключей
README.md                Установка, запуск и использование
```

## Что хранится в Git

Код, исходные SVG, каталог, документация, тесты, примеры, файлы зависимостей
и шаблон настроек. Каталог сохраняется в Git, чтобы первый запуск не требовал
предварительной обработки исходников. SVG не нормализуются Git по окончаниям строк.

## Что остаётся только локально

Виртуальное окружение Python, установленные npm-пакеты, кэши, реальные ключи
в `.env`, временные выгрузки в `exports/`, сгенерированные контактные листы,
инструменты чтения видео `.video-tools/` и `video-contact.jpg`.
Они не нужны пользователю для запуска приложения. Зависимости устанавливаются
по файлам зависимостей, а не копируются из компьютера разработчика.

## GitHub

Сначала создать пустой репозиторий без автоматически добавленных README,
лицензии и .gitignore. Затем подключить его HTTPS-адрес как `origin`.
Адрес и видимость репозитория выбирает владелец проекта. До появления origin
все коммиты остаются только на локальном компьютере.
