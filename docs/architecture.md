# Архитектура и порядок разработки

## Поток данных

```text
Названия / карточки ───────────────────────────┐
                                             ↓
Метафора → Groq → проверенные id и роли → компоновщик → JSON-сцена
                                                        ↓
Исходные SVG + роли палитры ─────────────────────→ SVG-рендерер
                                                        ↓
                                               редактор / экспорт
```

## Хранение и извлечение

Из Figma экспортированы отдельные группы предметов, а не растр всей страницы.
Архивы L/S распакованы в `assets/source`. 10 предметов имеют по четыре варианта:
L/S × главный/фоновый. Дополнительно есть шесть фонов. Образцы цветов и два
неидентифицированных мелких фрагмента оставлены в исходниках для аудита,
но не включены как предметы. Подробности — [asset-audit.md](asset-audit.md).

`scripts/prepare_assets.py` сопоставляет безымянные группы семантическим именам,
читает viewBox и записывает SHA-256. Каталог хранится в Git: старт приложения
не требует Figma или предварительной обработки. Исходные файлы не переписываются.

## Сцена и переиспользование

Сцена содержит ширину/высоту, L/S, палитру, общий scale и массив экземпляров:
`id, x, y, angle, role`. Порядок массива задаёт слои. Дубликат — новый экземпляр
с тем же id, а не новая иллюстрация. Нет индивидуального масштаба: соотношения
размеров берутся из исходного набора. S подменяет источник, а не просто уменьшает L.

В `app/main.py` находятся модели Pydantic, HTTP-маршруты, цветовые роли и
SVG-сборка. `app/layout.py` содержит размещение главного объекта и окружающих
элементов. Остальные схемы используют расчёт рядов, диагональное смещение или
резервирование места под заголовок. Все схемы используют общий масштаб.
Адаптация формата сохраняет нормализованные центры; при смене S/L компенсирует
номинальное двукратное различие размеров. Индивидуальные особенности оригиналов
S (например, размер монеты) остаются свойствами библиотеки.

## Векторный экспорт

Сервер читает оригинальные SVG через ElementTree, копирует содержимое, меняет
только значения цветовых ролей и добавляет групповые transform. Каждый экземпляр
получает уникальные id, локальные ссылки на определения переназначаются.
Корневые атрибуты исходников сохраняются. Фон кадрируется с сохранением пропорций.
SVG не содержит внешних растров, не требует сервера и открывается самостоятельно.

Экспорт и предпросмотр создаёт одна функция `render_svg`, что исключает отдельную,
потенциально расходящуюся реализацию экспорта. JSON-проект сохраняет модель сцены,
а не SVG-разметку, и при открытии заново валидируется сервером.

## ИИ

`app/ai.py` отправляет Groq только тему и текстовый каталог. Модель возвращает
id, роли и краткое объяснение. Сервер проверяет типы, количество, отсутствие
повторяющихся/неизвестных id и наличие главного объекта. Модель не получает
возможности выполнять код, изменять файлы или генерировать SVG.

Ключ читается из окружения процесса или корневого `.env`. Он не попадает в
ответы API, клиентский JavaScript и сохранённые проекты. Ошибки провайдера
переводятся в понятные сообщения, без вывода тела ответа с потенциальными секретами.

## Клиент

`web/app.js` отвечает за библиотеку, сборку, перетаскивание, поворот и слои.
`web/editor.js` добавляет историю, автосохранение, импорт проектов/палитр,
примеры и адаптацию формата. Изображение остаётся SVG DOM, а не canvas-растром.
Временные изменения положения/поворота показываются сразу; окончательный SVG
проверяется сервером. Устаревшие ответы предпросмотра отсеиваются номером запроса.

## Как делали по порядку

1. Разобрали ТЗ и скриншоты: запрет новых объектов, векторность, варианты S/L,
   основные/фоновые состояния, цветовые роли и комплект сдачи.
2. Проверили общий SVG-экспорт и выяснили, что экспорт отдельных групп удобнее.
   Получили два архива L/S, построили контактные листы и каталог.
3. Настроили Git/SSH, `.gitignore`, сохранение оригинальных SVG без нормализации
   окончаний строк, виртуальное окружение и фиксированные зависимости.
4. Реализовали путь «предметы → раскладка → SVG», затем ручной редактор.
5. По пользовательской видеопроверке уточнили названия слоёв и поведение поворота.
6. Подключили Groq, проверку его ответа, кеш и ограничения запросов.
7. Добавили сохранение правок при смене формата, историю, проекты и палитры.
8. Дополнили выразительную раскладку, три независимых от API примера,
   автоматические проверки и документацию для сдачи.

## Почему такой стек

Python соответствует исходному опыту автора; FastAPI даёт компактный HTTP API
и валидацию через Pydantic. Обычный JavaScript достаточен для одного редактора,
поэтому нет обязательной сборки frontend и Node.js при запуске. Файловая
библиотека мала и неизменяема, база данных не нужна. Figma использовалась как
источник ассетов, а не как обязательная среда работы проверяющего.
