# Очень · конструктор векторных иллюстраций

Веб-сервис для тестового задания: собирает новые композиции **из предоставленных SVG-объектов** по метафоре, заголовку или названиям предметов. ИИ выбирает содержимое сцены, а Python размещает и экспортирует исходные векторы. Новые изображения не генерируются.

![Пример: командная работа](docs/teamwork.png)

**Быстрая проверка:** запустите приложение и нажмите один из трёх готовых примеров над холстом. Для этого API-ключ не нужен. Примеры можно редактировать и экспортировать.

[Демонстрация](docs/demo.md) · [Соответствие ТЗ](docs/requirements.md) · [Архитектура и этапы](docs/architecture.md) · [AI-инструменты](docs/ai-tools.md) · [Проверки](docs/verification.md)

## Что умеет

- **По идее:** Groq анализирует метафору/заголовок, выбирает 1–5 существующих объектов, назначает главные и фоновые роли и объясняет выбор.
- **По предметам:** карточки библиотеки или названия через запятую: `Книга, лампа, наушники`.
- Четыре раскладки: выразительная композиция, сбалансированная, диагональная и со свободным местом под заголовок.
- Квадратный, горизонтальный и вертикальный холст; оригинальные варианты детализации L/S.
- Перемещение, поворот, дублирование, удаление, смена состояния и порядка слоёв.
- Три встроенные цветовые схемы и загрузка пользовательской палитры в JSON.
- Отмена/повтор, автосохранение в браузере, сохранение и открытие JSON-проекта.
- Экспорт самостоятельного SVG с отдельными группами предметов, без растровых вставок.

## Запуск

Нужен **Python 3.12**. Node.js, Figma, база данных и API-ключ не нужны для ручного конструктора и готовых примеров.

### Windows

Скачайте репозиторий или клонируйте:

```powershell
git clone https://github.com/condorTes/ochen-illustration-builder.git
cd ochen-illustration-builder
```

Запустите `run.bat`: он создаёт `.venv`, устанавливает зависимости и запускает сервер. Альтернатива — команды вручную:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-lock.txt
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

### macOS / Linux

```bash
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements-lock.txt
.venv/bin/python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Откройте **http://127.0.0.1:8000**. Остановка — `Ctrl+C`. Для разработки можно добавить `--reload`.
Если порт занят, используйте `--port 8001` и соответствующий адрес. После обновления исходников обновите страницу через `Ctrl+F5`.

Над холстом есть три кнопки готовых примеров. Они загружают сохранённые сцены, **не имитируют новый ответ ИИ**. Все функции редактирования и экспорта доступны.

| Пример | Формат | Исходники |

## Подключить подбор по метафоре

1. Создайте ключ в [Groq Console](https://console.groq.com/keys).
2. Скопируйте `.env.example` в `.env` в корне проекта.
3. Укажите ключ только в локальном файле:

```dotenv
GROQ_API_KEY=ваш_ключ
GROQ_MODEL=openai/gpt-oss-20b
```

4. В интерфейсе слева выберите **«По идее · ИИ»**, введите «Инвестиции в знания» и нажмите «Собрать композицию».

В Groq отправляются текст идеи и текстовый каталог. SVG не отправляются. Ответ модели проверяется: неизвестные предметы, неверные роли и некорректная структура отвергаются. Ключ не возвращается в браузер и не включается в JSON/SVG. `.env` исключён из Git.

Доступность модели и бесплатные квоты зависят от аккаунта Groq. При ошибке сервис показывает сообщение; ручной режим продолжает работать. Повторные идеи кешируются на час в памяти процесса. Приложение ограничивает обращения к модели: 5 в минуту и 40 в час на процесс.

## Палитра

Справа нажмите «Скачать образец» или используйте [examples/palette.json](examples/palette.json). Измените цвета и выберите «Загрузить палитру»:

```json
{
  "name": "Моя палитра",
  "background": ["#D7CDF5", "#AA9BF0", "#7864D7"],
  "objects": ["#F9ECB0", "#F9A3AA", "#FFE3E1"]
}
```

В каждой группе ровно три HEX-цвета. `background` заменяет роли фоновой палитры и допустим в основных предметах. `objects` применяется только к основным предметам. Чёрные контуры и белые участки сохраняются. Произвольный CSS не принимается.

**Трактовка неоднозначности ТЗ:** запрет менять цветовую схему фона понимается как запрет смешивать роли и окрашивать фон цветами основных объектов. Переключение целой схемы и замена её фоновых ролей разрешены, поскольку ТЗ отдельно требует загрузку палитры и автоматическую перекраску. Геометрия фона сохраняется. Это решение явно выделено в [соответствии ТЗ](docs/requirements.md).

## Редактирование и сохранение

- Перетащите предмет мышью; выберите его на холсте или в списке слоёв.
- «На слой вперёд/назад» меняет перекрытие предметов, а не координату по вертикали.
- Общий масштаб сохраняет соотношение размеров исходников; индивидуального растяжения предметов нет.
- При смене формата/S/L сохраняются дубликаты, повороты, состояния и порядок слоёв. Центры адаптируются к холсту.
- Смена раскладки заново рассчитывает позиции, сохраняя роли, повороты и количество экземпляров.
- `Ctrl+Z` / `Ctrl+Shift+Z` — отмена/повтор вне текстовых полей. История до 60 состояний сохраняется до обновления страницы.
- Последняя сцена автоматически хранится в localStorage этого браузера. Ключей и текста запроса в сохранённой сцене нет.
- **«Сохранить проект»** — JSON для продолжения работы; **«Скачать SVG»** — готовый вектор для использования в дизайне.

## Стек и устройство

**Python 3.12, FastAPI, Pydantic, Uvicorn; HTML/CSS, обычный JavaScript, SVG DOM; Groq API.**

Библиотека — локальные SVG и JSON-каталог, без базы данных. `requirements-lock.txt` фиксирует проверенные версии. Node.js + Sharp применялись только для иллюстраций документации, PyAV/Pillow — для разбора пользовательских видеозаписей; приложению они не нужны.

```text
app/              API, компоновка, SVG-экспорт, интеграция Groq
web/              Интерфейс и история редактора
assets/source/    Неизменённые оригиналы L/S
assets/catalog.json  Имена, теги, варианты, viewBox, SHA-256
examples/         Три сцены в SVG/JSON и пример палитры
tests/            Проверки геометрии, сцен, палитр и ответов модели
scripts/          Подготовка каталога и воспроизводимых примеров
docs/             Архитектура, ТЗ, демонстрация, отчёт проверок
```

Подробно о хранении, извлечении и переиспользовании — в [архитектуре](docs/architecture.md).

## Проверки

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Тесты не обращаются к платным API. Они проверяют исходные хеши и контуры, уникальность SVG-id, границы автоматических раскладок, цветовые роли, сохранение дубликатов/правок и валидацию ответа ИИ. В репозитории есть GitHub Actions для тех же проверок.

## Область применения и ограничения

Это локальное тестовое приложение с подготовленной библиотекой. Нет регистрации, совместного редактирования и загрузки произвольных SVG. Подготовленная библиотека разрешена ТЗ. Автоматическая композиция использует правила и шаблоны; художественный выбор модели и размещение можно поправить вручную.

При ручном перетаскивании/повороте допускается выход предмета за холст; экспорт обрезается по границам холста. Полного оптического анализа пересечений контуров нет. Экспорт проверен структурно и независимым SVG-рендерером; отдельный импорт в Figma в этой сессии не подтверждён.

Сервер по умолчанию доступен только на вашем компьютере. Для публичного размещения нужны авторизация, HTTPS и общий лимит API, устойчивый к перезапускам и нескольким процессам. Открытый демосервер с личным ключом не развёрнут.

Исходные иллюстрации предоставлены для тестового задания. Репозиторий не предоставляет дополнительную лицензию на их использование.
